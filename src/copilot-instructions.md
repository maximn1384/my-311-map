# Copilot Instructions: Power Apps Code App - 311 Map

## 1. Context and Architecture
* **Project Type:** Microsoft Power Apps Code App (React + TypeScript).
* **Environment:** This app is deployed inside a Dynamics 365 Customer Service environment.
* **Goal:** Display Dynamics 365 Customer Service Cases (`incident` table) on a geographic map based on their latitude and longitude coordinates.

## 2. UI and Styling Rules
* **Component Library:** You MUST exclusively use `@fluentui/react-components` (Fluent UI v9). Do NOT use `@fluentui/react` (v8), Material UI, Tailwind (unless pre-configured in the starter template), or raw CSS.
* **Theming:** The app must respect the Power Apps theme context. Use standard Fluent UI v9 tokens (e.g., `tokens.colorBrandBackground`) for all custom styling via `makeStyles`.
* **Icons:** Use `@fluentui/react-icons`.

## 3. Data Integration (Dataverse)

### General Rules
* **No Direct APIs:** Do NOT write custom `fetch` or `axios` calls to the Dataverse Web API.
* **Proxy Classes:** Use exclusively the typed services generated by the Power Platform CLI in `src/generated/services/MicrosoftDataverseService.ts`.
* **Table:** Primary table is `incident` (Cases). Custom coordinate fields are `hippo_latitude` and `hippo_longitude` (Decimal, publisher-prefixed).
* **Mocking:** Use a `ServiceFactory` pattern. `MockCaseService` is used in dev (`import.meta.env.DEV`), `DataverseCaseService` in production builds.

### Known SDK Quirks (discovered in production)

**`EntityItem.dynamicProperties` is a TypeScript-only artifact.**
The generated `EntityItem` interface exposes fields via `dynamicProperties?: Record<string, unknown>`, but at runtime Dataverse fields are directly on the item object. Always cast the item directly:
```ts
// CORRECT
const p = item as unknown as Record<string, unknown>
// WRONG — dynamicProperties is always undefined at runtime
const p = item.dynamicProperties ?? {}
```

**Use `ListRecordsWithOrganization`, not `ListRecords`.**
`ListRecords` (current environment) fails in production with `"Invalid organization URL 'null' provided"` because the API Hub cannot resolve the org URL from the connection context. The correct pattern:
1. Call `GetOrganizations()` once to discover the org URL — result is cached in `src/services/orgContext.ts`.
2. Pass that URL to `ListRecordsWithOrganization(orgUrl, entitySetName, ...)`.

**Entity set name must be plural with `ListRecordsWithOrganization`.**
`ListRecords` handles pluralisation internally. `ListRecordsWithOrganization` passes the name directly into the OData URL path (`/api/data/v9.1/{name}`), so you must use the plural entity set name:
```ts
// CORRECT
ListRecordsWithOrganization(orgUrl, 'incidents', ...)
// WRONG — causes "Resource not found for the segment 'incident'"
ListRecordsWithOrganization(orgUrl, 'incident', ...)
```

**`GetOrganizations()` returns a Power Platform proxy URL, not the real CRM URL.**
The `Url` field from `GetOrganizations()` is a `powerplatformusercontent.com` proxy URL that works for SDK API routing but is NOT a valid browser navigation URL. Do NOT use it to construct `window.open()` navigation links. For navigation URLs use `VITE_ORG_URL` from `.env.production` (see Section 5).

### Error Handling
Always extract `isError` and `error` from TanStack Query hooks and display them explicitly. A silent empty state (returning `data = []` on error) makes debugging in production very hard:
```tsx
const { data: cases = [], isLoading, isError, error } = useCases()
// render <MessageBar intent="error"> when isError is true
```

## 4. Mapping

### Library Decision
**Use `react-map-gl` + `maplibre-gl` with OpenStreetMap raster tiles.** Do NOT use `react-leaflet` or Azure Maps.

* **`react-leaflet` is blocked** by the Power Apps host Content Security Policy (`img-src 'self' data:`). Leaflet renders tiles as `<img>` elements, which are blocked.
* **`azure-maps-control`** requires an Azure Maps subscription key — unnecessary for MVP.
* **`maplibre-gl`** renders via WebGL canvas (bypasses `img-src` CSP) and is the correct choice.

### CSP Requirement (critical)
MapLibre GL requires Web Workers (`worker-src`) and external tile fetches (`connect-src`), both of which are blocked by the Power Apps host CSP by default.

**The "Enforce content security policy" setting must be disabled** in the Power Platform admin portal for this app to function:
> Power Platform Admin → Environments → [env] → Settings → Product → Privacy + Security → uncheck "Enforce content security policy"

### Map Style
Tile source is OpenStreetMap. The map style is defined as an inline `StyleSpecification` object (not a URL) — see `src/components/map/CaseMap.tsx`.

## 5. D365 Navigation

### `Xrm` is NOT available in Code Apps
`Xrm` is only injected by the D365 host into PCF controls and model-driven web resources. It is never available in Power Apps Code App iframes. Do NOT use `Xrm.Navigation.openForm()`.

### Navigation via `window.open`
Construct standard `main.aspx` URLs using the org URL and D365 app ID baked in at build time:
```ts
const ORG_URL = import.meta.env.VITE_ORG_URL   // e.g. https://org744e75ab.crm.dynamics.com
const APP_ID  = import.meta.env.VITE_D365_APP_ID // e.g. acc17fd0-9e46-ef11-a317-6045bda86808

// Open existing record
window.open(`${ORG_URL}/main.aspx?appid=${APP_ID}&pagetype=entityrecord&etn=incident&id=${incidentid}`, '_blank')

// Open new record form
window.open(`${ORG_URL}/main.aspx?appid=${APP_ID}&pagetype=entityrecord&etn=incident`, '_blank')
```

These values are set in `.env.production` (gitignored — must be recreated per machine/environment).

## 6. Deployment

### Required `.env.production`
Before every production build, `.env.production` must exist in the project root:
```
VITE_ORG_URL=https://<your-org>.crm.dynamics.com
VITE_D365_APP_ID=<model-driven-app-id>
```
This file is gitignored. Obtain `VITE_D365_APP_ID` from the D365 Customer Service app URL (`appid=` query parameter).

### Deploy Steps
```bash
npm run build          # TypeScript compile + Vite production build
npx power-apps push    # Upload dist/ to Power Apps environment
```

### Power Platform Admin Requirements
1. **CSP enforcement disabled** — required for MapLibre GL to load tiles and workers (see Section 4).
2. **Dataverse connection configured** — the app's connector must be authorised in the Power Apps portal.

## 7. Coding Standards
* **Language:** Strict TypeScript. No `any` types. Define clear interfaces for all data models (e.g., `ICase`).
* **Components:** Functional components and React Hooks (`useState`, `useEffect`, `useMemo`).
* **Pacing:** Do not build the entire app at once. Wait for specific feature requests. If a step requires a terminal command (`npm install`, `npx power-apps push`), confirm it succeeded before writing dependent code.
